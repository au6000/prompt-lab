# plab-survey

`plab survey` を流し、因子ごとの読み (`stable`・`partly`・`moving`・`none`・`few`) と学び直した利得から、探索を始めるかを決めて報告する。
数の定義と読み方は README.ja.md の 7 章にあり、ここには写さない。開いてはいけない物は、`plab brief` の指示の「What you must not open」と同じ。

## 始める前に決める物

- 課題のフォルダ: `-C` に渡す道。頼まれた文になければ、研究を回す人に聞く。以下では `DIR` と書く。
- `--gap`: 結果が分かるまでの月数。分からなければ研究を回す人に聞く。聞けなければ 0 で流し、そのことを報告に書く。

流すのは `plab split` のあと、探す人が最初の歩に入る前。研究が閉じたあと (本番が済んだあと) に、何が残り何が残らなかったかを知りたいときは `--splits all` を足す。

## 守ること

- `--splits all` は閉じた研究でだけ流す。閉じる前は plab が断る (終わりの番号 2)。断られたら学習の組だけで続ける。
- `--splits all` で調べた因子は、評価と本番の行を見ている。その因子を次の研究で使うなら、調べた最後の月より後の行で本番を流すことを、次の研究の事前登録に書く。
- 数は計算し直さず、plab の出力から読む。読みは plab が付けた語をそのまま使う。

## 手順

1. `plab -C DIR survey --json` を流す。`by_class` の `units_in_class` を見出しの `periods` で割り、40 以上なら `--by quarter`、10 未満なら `--by year` で 1 回だけ流し直してそちらを使う。この数は読みを見る前に決め、読みを見てから選び直さない。
2. `by_class` ごとに `summary` を読む。`stable` と `partly` の数を `by_chance` と比べ、`sigma_floor` を確かめる。結果が 3 つ以上の値を取る課題では、値ごとに次の表で読む。
3. 行を見る前から仕組みの理由がある事由 (決まった時刻の窓、予定された出来事など) を研究を回す人が持っていれば、1 本のプロンプトにして `plab -C DIR survey PROMPT --json` を流す。同じ行を探して見つけた事由は、`mu` が実際より大きく出ていると読む。
4. 次の表で決めて報告する。

## 決め方

数の目安はこのスキルの決めごとで、ここにだけ書く。表の上の行から順に当て、最初に当たった行で決める。

| 当たる形 | 決めること |
|---|---|
| `sigma_floor` がいちばん大きい `\|mu\|` より大きい、またはほとんどの因子が `few` | この行の数では分からない、と報告する |
| `stable` と `partly` の合計が 2 以上で `by_chance` の 3 倍以上、かつ `largest_stable.nats_per_year` に学習の組の年数 (`months` ÷ 12) を掛けた数が 5 以上 | 探索を始める。`stable` と `partly` の因子を、plab-search の向きとして渡す |
| 読みのほとんどが `moving` | 固定したプロンプトの探索は始めない。短い窓 (`pq 6`・`pq 12`) に `*` があれば、学び直せば使える情報があると書く。1 回だけの本番ではそれを測れないので、研究を回す人に判断を頼む |
| 読みが `by_chance` と同じくらいで、どの窓にも `*` が無い | 探索を始めない。もっと長い期間、もっと多くの行、別の結果、新しい欄のどれかを提案する |

どの行にも当たらなければ、いちばん近い行で決め、何が足りなかったかを報告に書く。
`stable` は探索を始めるのに要る形で、それだけで足りる形ではない。学習の組だけの survey では、学習の組のすぐあとに向きが変わる事由も `stable` に見える。

## 報告

研究を回す人に、次を渡す。

- 流したコマンド (`--by` を流し直したなら、その理由の数も)
- 見出しの数: 行、期間、予想した月
- `summary` の数と、決めに使った因子の行
- 決めたことと、表のどの行に当たったか
- survey が EXPLORATORY だったか (`--splits all` を流したか)
