# plab-search

prompt-lab の課題のフォルダで、探す人としてプロンプトを書き、学習の組で測り、結果を見て直すことを繰り返す。探すのを止めたら、評価の組で少しだけ確かめてから推す。推した物から選ぶことと本番の組を流すことは、研究を回す人がする。

読んでよい物、開いてはいけない物、使ってよいコマンド、上限、報告の形は、`plab brief` が出す指示に書いてある。このスキルはその中身を写さず、指示を受け取ったあとに案を直し続ける手順だけを決める。

## 始める前に決める物

- 課題のフォルダ: `-C` に渡す道。頼まれた文になければ、研究を回す人に聞く。
- エージェント名: 頼まれた名前。なければ `opus1`。
- 向き: 頼まれた向き。なければ `(free)`。
- 歩数の上限: 頼まれた数。なければ 10。
- 評価の組の使い方: `DIR/prereg.md` に、評価の組を見ながら探すと書いてあれば、下の「評価を見ながら探すとき」に従う。書いていなければ、評価の組は探すのを止めてから確かめる (「確かめと推薦」)。

`plab --help` が通らなければ、prompt-lab のリポジトリで `pip install -e .` を流すよう、研究を回す人に頼む。

以下では課題のフォルダを `DIR`、エージェント名を `A` と書く。

## 守ること

- 最初に `plab -C DIR brief --agent A --direction "向き"` を流し、その指示に従う。
- 指示の「What you must not open」に挙がった物は、Read でも Bash の `cat` や `grep` でも開かない。
- `task.json` と `prereg.md` は書き換えない。
- 鍵のファイル (`PLAB_KEY_FILE` が指す物) と `AI_GATEWAY_API_KEY` の値は、開かず、表示もしない。
- `--yes` は付けない。費用の見積もりが予算の残りを超えて断られたら、そこで止めて研究を回す人に伝える。
- 案のファイルとメモは `DIR/prompts/A/` にだけ書く。

## 1歩の進め方

新しい課題では、最初の歩の前に、スキル `plab-survey` で時間をまたいで残る情報があるかを確かめる。済んでいれば飛ばす。

最初の歩の前に、`plab -C DIR fields --auc` と学習の組 (`DIR/.plab/data/train.jsonl`) を読み、結果に関わりそうな欄の見当を付ける。

1歩ごとに次の順で進める。

1. 案を1〜3本書く。最初の歩では指示と向きから考えた案を書く。2歩目からは今の最良の案を1か所だけ変える。事由を1つ足すか、1つ外すか、1つ書き換えるかのどれかにすると、何が効いたかを分けて読める。
2. 案ごとに `plab -C DIR lint 案` を流し、出た警告を直す。
3. `plab -C DIR run 案 --decider machine --agent A --json` で測る。`expr` で書けない事由がある案だけは、`--decider` を付けずに課題の答える側で測る。こちらは費用がかかる。答える側を比べるときは `--decider machine --decider 名前` のように並べ、その歩で変えた1か所として数える。
4. 下の「最良の決め方」で、今の最良を替えるかを決める。
5. `DIR/prompts/A/notes.md` にその歩の分を書き足す。書くのは歩の番号、変えた所、そう考えた理由、結果の数、最良を替えたかどうか。

学習の組で測った回数は記録され、研究の報告に出る。案を多く試すほど、学習の組でいちばん良く見える数は実際より良く出る。数を打つより、理由のある案を少なく試す。

## 最良の決め方

学習の組の結果だけで決める。次の条件をすべて満たす案のうち、`cv_gain_pct` が今の最良より大きい案を、新しい最良にする。値 (`decision.gain_vs_all_in_per_1000`) は条件にだけ使い、比べる数には使わない。比べる数を2つにすると、どちらで比べたかで最良が入れ替わるためである。

- `null_pct.cv_gain_pct` (でたらめな答えの中での `cv_gain_pct` のパーセンタイル) が 95 以上。これより下は証拠にならない。
- `auc_h1` と `auc_h2` がどちらも 0.5 を超える。
- `decision.gain_vs_all_in_per_1000` が 0 を超える。
- `plab -C DIR drift 案 --by year` の表で、どの年でも効き方が逆になっていない。予想と値がある課題では見送った側の正例の率を、それ以外では選択肢ごとの正例の率を、年ごとに見比べる。drift は run と同じ答える側で流す。

予想 (`forecast`) を書かない案や、結果が3つ以上の値を取る課題、値の欄がない課題では、出ない数がある。出ない数の条件は飛ばす。

数がほとんど同じなら、仕組みの理由 (決まった時刻の窓、予定された出来事など) を言える方を取る。それでも決まらなければ、事由が少ない方を取る。

同じプロンプトを2つの答える側で測ったら、別の案として扱い、上と同じ条件と `cv_gain_pct` で比べる。数がほとんど同じなら、費用のかからない方を取る。

## 止め方

次のどれかに当たったら止める。

- 歩数が上限に届いた。
- 3歩続けて最良が替わらなかった。1回目は、まだ見ていない欄か別の種類の事由に、効きそうだと言える理由があればそこに移って続ける。理由のある移り先がなければ、そこで止める。移ったあとも3歩続けて替わらなければ止める。
- 予算で断られた。
- 評価を見ながら探すときは、確かめの上限に届いた。

## 確かめと推薦

評価の組の確かめ (`plab check`) は探すのを止めてからまとめて使う。評価を見ながら探すときは、次の節に従う。

- 確かめるのは最良の案と、もう1本までにする。もう1本は、最良の案から理由がいちばん弱い部分を1つ外した案にする。外す部分 (事由・問い・選択肢のどれか) は、その時期だけの事情に頼っていそうな物から選ぶ。
- 2本を比べれば、外した部分が評価の組でも効くかが分かる。2番目に良い案は最良の案とほとんど同じことが多く、比べても分かることが少ない。
- `check` と `nominate` には、`run` で測ったときと同じ `--decider` を付ける。推す物はプロンプトと答える側の組で、付けなければ課題の答える側で測られる。
- 確かめの結果では、`cv_gain_pct` とそのパーセンタイルに加えて、`transfer_gain_pct` を読む。これは学習の組で覚えた向きのまま評価の組を測った数である。`cv_gain_pct` より大きく下がっていたら、学習の組のあとで向きが変わった部分が混ざっている。
- 確かめた結果を見て案を直し、また確かめることはしない。確かめは当てはまり過ぎを見るためのもので、案を合わせ込むためのものではない。
- 推す案 (`plab nominate`) は学習の組の結果と確かめの結果を見て、推薦の上限の中で決める。確かめた2本のどちらを推すか迷ったら、`transfer_gain_pct` の大きい方を取る。推した物から選ぶのは、事前登録した選び方に従う `plab select` で、探す人ではない。

## 評価を見ながら探すとき

深層学習で検証データの精度を見ながら止めどきや設定を決めるのと同じく、学習の組で案を作り、評価の組の確かめで探す向きを決める。決め手は本番の組の1回で、探す人は本番の組に触れない。

- 学習の組で最良が替わった案か、理由のある新しい向きの案ができたら、評価の組で確かめてよい。確かめは1歩に1回までにし、上限の2割ほどは最後に案どうしを比べるために残す。
- 評価の組で落ちた事由は、学習の組で落ちた理由を探す。たとえば、ある年だけに頼っていないか、負けが同じ日に固まっていないかを見る。理由が分かったら、外すか書き直す。評価の組で残った事由は、それを軸に学習の組で広げる。
- 閾値や時間帯の端を、評価の組の数だけを手がかりに細かく動かして確かめ直すことはしない。学習の組で理由を言えない変更は、評価の組への合わせ込みになる。
- 確かめの数どうしを引き算したり組み合わせたりして、評価の組の一部の行の件数や負けの数を推し量らない。それは評価の組の中身を読むことになる。確かめの数は、その案全体の精度として読む。
- 確かめのたびに、`notes.md` に、何を確かめ、何が分かり、次にどう変えるかを書く。
- `check` と `nominate` には、`run` で測ったときと同じ `--decider` を付ける。
- 推すのは、確かめた案のうち、事前登録した選び方で条件を満たし、並べ方で上に来る物にする。満たす案が無ければ、条件にいちばん近い物を推し、満たしていないことを報告に書く。
- 評価の組の数は、見た回数だけ実際より良く出る。報告には、評価の組を何回見たかを書く。

## 報告

指示の「Report back」の形で、研究を回す人に報告する。`notes.md` の道と、止めた理由も添える。

## 続きから始めるとき

`DIR/prompts/A/notes.md` と `plab -C DIR board --split train --agent A` を読み、最後の歩の次から始める。歩数は通しで数える。

## 並列で探すとき

研究を回す人に頼まれたときだけ、探す人を何人も同時に走らせる。このとき自分はまとめ役として動く。

- 人数は事前登録に書いた数までにする。書いていなければ、何人にするかを研究を回す人に確かめる。評価の組を見る回数の合計は、人数と1人あたりの上限を掛けた数になる。
- 探す人ごとにサブエージェント (モデルは opus) を1人起動する。渡すのは課題のフォルダ、その人だけのエージェント名 (`s1`、`s2` など)、向き、歩数の上限、prompt-lab のリポジトリの `.claude/skills/plab-search/SKILL.md` を読んで従うことの5つ。
- 向きは重ならないように分ける。たとえば、時刻の窓と予定された出来事を見る人、値動きの比で書いた事由を見る人、言葉でしか書けない事由を見る人に分ける。
- 起動したら、全員が終わるのを待つ。まとめ役は探す人の作業を自分ではしない。
- 全員の報告をまとめて、研究を回す人に渡す。`plab select` と `plab test --final` は、研究を回す人が流す。
