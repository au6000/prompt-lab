# ADR-0012: 学習の組の fitted の予想では、AUC を分割の中で測り、分割をまたいで行を比べる物差しを出さない

状態: 採用 (2026-11-22)

## 背景
`forecast: "fitted"` の予想は、学習の組では交差検証の外の予測です。行ごとに、その行の入っていない分割で当てはめた V で予想します。
2026-11-21 までは、この予想を分割をまたいでひとまとめにし、AUC・区間 MI・五分位・交差当てはめを測っていました。
合成の数 (1,500 行、月ごとに正例の率が動く、40 回の平均) では、答えそのものの AUC が 0.530 なのに、予想の AUC は 0.429 で、40 回すべてで 0.5 を下回りました。効き目の無い答えでも、区間 MI は 2.04% に膨らみました (答えそのものは 0.06%)。
ある分割に正例が多いと、残りの分割で当てはめた V は正例を少なく見て、その分割の行を低く予想します。分割ごとの当てはめの違いが、その分割の正例の率と逆向きに動くためです。

## 決定
- 学習の組の fitted の予想の AUC (全体と前半・後半) は、分割の中で測り、正例と負例の組の重みで平均します (`cv_auc`)。
- 区間 MI・その p・五分位ごとの正例の率は None にし、交差当てはめは出しません。どれも分割をまたいで行を比べるためです。
- 判断の表は今までどおり出します。各行の見送りを、その行を見ていない当てはめで決めて数えるだけなので、偏りません。
- 評価と本番の組の fitted の予想は、学習の組の V をそのまま当てるので変わりません。

## 理由
分割の中では、すべての行が同じ当てはめで並ぶので、分割ごとの当てはめの違いが AUC に入りません。上の合成の数で、AUC は 0.528 (効き目なしで 0.503) になりました。
区間 MI と五分位は、分割の中で測ると揺れすぎます。1 つの分割は 100〜150 行しかなく、それを 5 つの区間に分けることになるためです。

## 捨てた案
- 傾きは分割の外で、切片は全部の行で当てはめる。AUC は 0.486 までしか戻らず、区間 MI も 0.33% 残り、判断の表に答えが漏れます。
- 学習の組の全部で当てはめた V で予想する。向きもその行の答えで決まるので、効き目の無い答えでも AUC が 0.5 を上回ります。

## 引き受けること
- 0.1 の `{"combine": "lr"}` のプロンプトは、移し替えると fitted になります。そのため学習の組の AUC は 0.1 と違う数になり、区間 MI と交差当てはめは出なくなります。
- 0.1 との一致を確かめる記録 (合成の例と FX の u3) には該当するプロンプトが無いので、`scripts/parity.py` ではこの違いが見えません。FX のフォルダにも、2026-11-22 の時点で `combine` を使うプロンプトはありません。
- 選び方が `train.mi_pct` や `train.xfit.*` を読むと、fitted の案はその条件で落ちます。

## 確かめ方
`tests/test_yardsticks.py` の `FittedForecastAUC`、`tests/test_prompts.py` の fitted の予想の検査。
