# ADR-0006: 手順は段階の表と Lock で守る

状態: 採用 (2026-11-20、0.2.0)

## 背景
0.1 は、事前登録が済んだか、本番が済んだかの確認が、いくつものコマンドに散っていました。
記録は全員で 1 つのファイルに追記していました。

## 決定
- 研究の段階をファイルから求め、どのコマンドがどの段階で動けるかを 1 つの表 (`PERMITS`) で決めます。
- 評価と本番の行は、事前登録を確かめたときにだけ作られる `Lock` を渡さないと読めません。
- 記録はエージェントごとのファイル (`.plab/agents/<agent>/`) に分けます。
- 同じエージェントの評価の確かめは `check.lock` を排他で作ってから数え、測り、追記します。
- 既定値は `task.py` の 1 か所に置きます。lock には `UNLOCKED` に挙げた設定以外を全部含めます。

## 理由
確認が散っていると、新しいコマンドで確認を忘れます。`Lock` が要る形にすれば、近くの呼び出しを写しただけのコードが評価の行を読めません。
Windows の Python の追記は「末尾へ移動」と「書く」の 2 段の動作なので、2 つの処理が同じファイルに追記すると上書きし合うおそれがあります。
lock を既定で全部にすれば、あとで足した設定が lock から漏れません。

## 捨てた案
- コマンドごとの確認。
- 全員で 1 つの記録のファイル。
- lock に含める設定を 1 つずつ挙げる。足し忘れた設定が lock から漏れます。

## 引き受けること
0.1 の記録の置き場 (`.plab/runs.jsonl` など) は使えなくなります。
害の無い設定 (既定の判定モデルの名前など) も lock されます。
