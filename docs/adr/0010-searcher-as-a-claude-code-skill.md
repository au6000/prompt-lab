# ADR-0010: 探す人は Claude Code のスキルとして動かし、promptlab に LLM を呼ぶコードを入れない

状態: 採用 (2026-11-21)

## 背景
Opus にプロンプトを書いて直し続けさせ、推すところまで任せたいと考えました。
ハーネスには探すエージェントのための物がすでにあります。`plab brief` が出す指示、エージェントごとの評価の確かめと推薦の上限、エージェントごとの記録、学習の組で測った回数の報告です。

## 決定
- 探す手順をリポジトリの `.claude/skills/plab-search/SKILL.md` に置きます。Opus は Claude Code の中でこのスキルに従い、`plab` のコマンドを流します。
- 読んでよい物、使ってよいコマンド、上限は `plab brief` の出す指示にだけ書きます。スキルはその指示を受け取り、案を直し続ける手順 (1歩の進め方、最良の決め方、止め方、確かめと推薦の順) だけを持ちます。
- 並列で探すときは、探す人ごとにサブエージェントを1人ずつ起動し、別のエージェント名で動かします。
- promptlab には LLM を呼ぶコードを入れません。依存は numpy のままです。

## 理由
手順の守りは CLI の側にあるので、探すのが人でも Opus でも、同じ上限と記録が働きます。
指示の本文が `plab brief` の1か所なら、スキルと食い違いません。
人が途中の案と記録を見られます。

## 捨てた案
- 無人で回す `plab search` コマンドを作り、Vercel AI Gateway を通して API で Opus を呼ぶ。promptlab に LLM を呼ぶコードと、案を出させるプロンプトの保守が入り、トークンごとに払うことになります。Claude Code の中で手順が固まってから、もう一度考えます。
- スキルに `plab brief` の中身を写す。同じ決まりが2か所になります。

## 引き受けること
費用は Claude Code の利用量で払うので、長く回すと5時間あたりの上限に当たります。
探す人が評価の組や本番の組のファイルを直接開くことは、スキルでもハーネスでも止められません。指示とスキルで禁じ、`plab` を通した確かめはすべて記録に残ります ([protocol.md](../protocol.md) の最後の節)。
並列の人数を増やすと、評価の組を見る回数の合計が増えます。人数は事前登録に書きます。

## 確かめ方
合成の例の写しで、探す人1人に、答える側を machine にして通させます。写しからは、例の `prompts/` にある答えの案 (`a_window.json` など) と、効き目を仕込む `make_data.py` を外しておきます。
働いていると言えるのは、推した物から事前登録の選び方が (a) の型を選び、(b) の型を選ばないときです。
2026-11-21 に1回流し、この条件を満たしました。探す人 (Opus) は10歩で13本の案を学習の組で測り、評価の組を2回確かめて時刻の窓の案を1本だけ推し、選び方はその案を選びました。24時間の動きの事由を含む案は、評価の組で効き目が消えたので推されていません。
選ばれた案には、データに仕込んでいない「毎時35〜39分」の事由も入っていました。
