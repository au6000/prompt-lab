# ADR-0004: 答えの記録の鍵は、判定モデルが読む物から作る

状態: 採用 (2026-11-20、0.2.0)

## 背景
0.1 はプロンプト全体の指紋を鍵にして答えを記録していました。式や名前を少し直すだけで、払った答えが使えなくなりました。
反対に、行の中身が変わっても、行の id が同じなら古い答えを使っていました。

## 決定
判定モデルごとに `reads(ask)` を持ち、そのモデルの答えを変えうる物を返します。答えの記録の鍵は `reads` が返した物の指紋にします。

- gateway の判定モデルは送る入力と問いを読みます。
- 偽の判定モデル (fake) は式も読みます。偽の答えは式から作るためです。
- 機械 (machine) の答えはその場で計算し、記録しません。

偽の判定モデルの乱数の種は 0.1 の作り方を残します。

## 理由
式を直しても、判定モデルに送る物が同じなら、払った答えを使い回せます。
行の中身や送る問いが変われば、古い答えは使われません。
書く LLM の文章や、行ごとの問い (第 2 段) も、同じ鍵で扱えます。

## 捨てた案
- 0.1 のプロンプトの指紋の鍵。
- gateway の判定モデルが見る物だけを、全部の判定モデルの鍵にする。偽の答えは式で変わるので、式を直しても古い答えが残ります。

## 引き受けること
偽の判定モデルの種には、0.1 の鍵の作り方が残ります。合成の例の数を保つためで、変えると偽の答えが全部変わります。

## 確かめ方
`tests/test_deciders.py` の「式を直しても判定モデルの答えは残る」「偽の判定モデルは取り直す」の検査。
